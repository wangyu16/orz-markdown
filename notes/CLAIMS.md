# orz-markdown claims registry

Each claim is one sentence that is true or false about the package, bound to an
oracle that decides which. A test proves a claim by carrying its id in its
title (`[C.3] …`). `tests/claims.test.ts` fails if a claim here has no test, or
a test names a claim that is not here — an unverified claim is red.

A known gap is kept as a **probe**: `it.fails('[ID] …')`, a strict expected
failure that turns red the day it starts passing, so the fix has to promote it.

Oracles: **scenario** (behaviour end to end), **conformance** (code obeys a
rule), **probe** (adversary's reproduction), **bound** (a measured cost),
**real** (runs on the real substrate — Chrome — because a fake cannot show it).
A **real** test skips when Chrome is not installed; such a run does not verify
those claims.

Round history and dismissals: [`closed-loop.md`](closed-loop.md).

## C — copy-as-Markdown (runtime)

The oracle for C.1–C.13 is the round trip: render Markdown → DOM → copy as
Markdown → render again; the two renders must be equivalent (ids ignored).

| ID | Claim | Oracle |
|---|---|---|
| C.1 | Copying a whole rendered English document yields Markdown that re-renders equivalently, for every construct in the edge corpus. | scenario |
| C.2 | The same holds for the Chinese (CJK) edge corpus. | scenario |
| C.3 | Text that only *looks* like Markdown — literal `* _ \` [ < {{ $ ~ ^ == ++ &entity;` and line-start `# > - + 1.` — is copied as literal text, never as syntax. | scenario |
| C.4 | Inline code containing backticks and code blocks containing fences survive the round trip. | scenario |
| C.5 | Hard line breaks survive (`\` + newline); in table cells they become `<br>`. | scenario |
| C.6 | Ordered lists keep their start number; list items with several blocks (paragraphs, code, quotes, nested lists) keep their structure and tight/loose spacing; task boxes belong only to their own item. | scenario |
| C.7 | Tables keep column alignment, literal `\|` in cells (also inside inline code), and empty cells. | scenario |
| C.8 | Links and images keep titles containing quotes, URLs containing spaces or parentheses, and `=WxH` image sizes; a bare autolink is copied as the bare URL where linkify finds exactly that URL again, and otherwise as `<url>` or `[text](url)` — never so that it links a different target. | scenario |
| C.9 | Footnote references and definitions are copied with their original labels (`[^note]`, `[^注]`, inline `^[…]`). | scenario |
| C.10 | Every container survives with its arguments: semantic, layout (`cols` ratios, `left` width), `spoil` labels containing Markdown, `tab` labels, custom `::: name`, and nesting at any depth. | scenario |
| C.11 | Generated constructs (mermaid, smiles, qr, youtube, chart, toc) copy back as their original directive. | scenario |
| C.12 | Stable block ids (`{{attrs[#blk-…]}}`) are never copied, so a pasted section cannot duplicate an id. | scenario |
| C.13 | Full-width spaces (U+3000) and non-breaking spaces survive; only ASCII whitespace runs collapse. | scenario |
| C.14 | The runtime does not take over a copy whose selection starts or ends outside the copy root, or inside an editable field; the browser's own copy proceeds. Copy roots may nest (`data-orz-copy` around `.markdown-body`): the nearest root holding both ends is used, so a partial selection never copies text outside it. | real |
| C.15 | In real Chrome, a user selection copied with the copy event yields Markdown on `text/plain`: a selection that takes a block element itself (select-all, a drag from before it, a range around it) copies that whole block — a code block fenced, a heading with its `#`, a list item with its marker — and one covering all of a table/quote/container copies that block; a partial selection copies only what is selected; text inside code copies verbatim; a selection cutting into inline math or a generated construct takes the whole element. | real |
| C.16 | Copy is linear and fast in Chrome: a 2,000-block mixed document, a 4,000-item price list and 4,000 tables each convert in well under a second on a laptop; the copy event itself, for a whole-document selection, scales with 4× the input under 8× the time; and copying two paragraphs costs the same in a long document as in a short one (ratios of best-of-three, stable under load). | bound |
| C.17 | Raw HTML that Markdown cannot express survives as HTML: inline `kbd`, `abbr`, `u`, `small`, `ruby`/`rt` (pinyin), spans with `style` or other attributes, and block `<details>` that is not a `::: spoil`. | scenario |
| C.18 | Inline formatting copies as delimiters only where they re-parse; where CommonMark flanking would fail (punctuation inside meeting a letter outside, padded content, adjacent same-kind runs) it falls back to the equivalent HTML tag. | scenario |
| C.19 | An include that `prepareSources` neutralized (`{{` + U+2060) copies as what the reader sees: inside code as the plain directive, in prose as the same literal text — never with the invisible joiner. | real |
| C.20 | `getBrowserRuntimeScript({ autoInit: false })` installs copy-as-Markdown without wiring QR expansion or tab bars; the default is byte-identical to `browserRuntimeScript`. | real |

## S — shell runtime (`orz-markdown/carrier/shell`)

The browser runtime every assembled file shares (`src/carrier/shell/`): the
standalone save, reader preferences, and both sides of the host protocols.
Specs: `spec/shell-runtime.md`, `spec/host-protocols.md`. Tests in
`tests/carrier-shell.test.ts`: decision logic against fakes (windows, pickers,
handle stores, storage, fake timers); bytes, cross-origin delivery,
`targetOrigin` filtering, IndexedDB, real file handles and downloads in real
Chrome (S.12; skipped without Chrome). The real save picker cannot be
automated: the Chrome tests replace it with a function returning a real
origin-private `FileSystemFileHandle`.

| ID | Claim | Oracle |
|---|---|---|
| S.1 | `createSaver().save({ text, html })` tries, in order, a connected host (`{via:'host'}`; a refused host save is reported, never downloaded), the served-page notice on an http(s) page with no handle this session (`{via:'served-notice'}`, no picker, no download; `download()` then saves a copy), File System Access when `showSaveFilePicker` exists (`{via:'file'}`), else a download of `suggestedName` (`{via:'download'}`) — and never rejects. | scenario |
